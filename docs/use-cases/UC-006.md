# UC-006 - El agente gestiona operaciones con autorización (human-in-the-loop)

| Campo | Valor |
|-------|-------|
| **ID** | UC-006 |
| **Título** | El agente gestiona operaciones con autorización (human-in-the-loop) |
| **Prioridad** | P3 |
| **Estado** | Aprobado |
| **Versión** | 1.0 |
| **Fecha** | 2026-08-11 |

## Actores

- **Usuario**: profesional de QA que controla las acciones que puedan
  modificar, eliminar o afectar información del proyecto.

## Descripción

Ante una acción que pueda modificar, eliminar o afectar información del
proyecto, el agente solicita autorización explícita antes de ejecutarla. Mientras
la acción sensible está pendiente de autorización, el agente suspende su
ejecución e informa al usuario. Si el usuario deniega la autorización, el agente
se abstiene de ejecutar la acción y notifica el resultado.

## Disparador

Durante cualquier interacción, el agente determina que una acción puede
modificar, eliminar o afectar información del proyecto (acción sensible).

## Precondiciones

1. Existe al menos una acción sensible identificada por el agente.
2. El usuario está disponible para otorgar o denegar la autorización.

## Flujo Principal

1. El agente identifica una acción potencialmente sensible (que puede
   modificar, eliminar o afectar información del proyecto).
2. El agente suspende la ejecución de dicha acción.
3. El agente solicita autorización explícita al usuario.
4. El agente informa al usuario cuál es la acción pendiente de autorización.
5. El usuario otorga la autorización explícita.
6. El agente ejecuta la acción autorizada.
7. El agente informa al usuario del resultado de la ejecución.
8. El caso de uso termina.

## Flujo de Excepción 5a - Autorización denegada

1. El usuario deniega la autorización.
2. El agente se abstiene de ejecutar la acción.
3. El agente notifica al usuario que la acción no se ejecutó.
4. El caso de uso termina.

## Flujo de Excepción 5b - Autorización pendiente

1. El usuario no ha respondido aún a la solicitud de autorización.
2. El agente mantiene la acción suspendida.
3. El agente continúa informando al usuario que la acción está pendiente de
   autorización.
4. El caso de uso permanece en este estado hasta recibir una decisión.

## Postcondiciones

1. Ninguna acción sensible se ejecuta sin autorización explícita.
2. Si la acción fue autorizada, se ejecutó y se notificó el resultado.
3. Si la acción fue denegada, no se ejecutó y el usuario fue notificado.
4. La autonomía del agente nunca se impone sobre las políticas de seguridad.

## Trazabilidad

- **User Story**: US-6 (El agente gestiona operaciones con autorización).
- **Requisitos funcionales**: FR-015, FR-016, FR-025.
- **Principios de la constitución**: IV (Seguridad y mínimo privilegio), V
  (Human-in-the-loop).
- **Criterios de éxito**: SC-004, SC-011.

## Notas

Caso de uso **transversal**: sus reglas aplican como restricción sobre cualquier
otro caso de uso (UC-001 a UC-005) en el que pueda surgir una acción sensible,
como ejecutar un comando que modifique o elimine información. Las acciones
destructivas o irreversibles están restringidas y sujetas a protección adicional.
