# UC-013: El agente explica con profundidad qué hace cada capa y qué pruebas la cubren

## Objetivo
El usuario solicita al agente **explicar o entender el código** del proyecto:
qué hace cada capa o módulo, qué pruebas lo cubren o cómo funciona un archivo.
El agente lee el **contenido real** de los archivos relevantes
(`leer_archivo`), organiza la respuesta por capa/módulo citando lo observado y,
si la evidencia no alcanza, responde con honestidad y `confianza` coherente.

## Actores
- **Usuario** (humano) — solicita la explicación del código.
- **Agente** (bucle ReAct) — planifica pasos de lectura, ejecuta herramientas,
  evalúa la evidencia y responde con profundidad.
- **Herramienta `leer_archivo`** — lee el contenido real de un archivo dentro
  del perímetro (solo lectura, `requiere_autorizacion=False`).
- **Herramientas auxiliares** — `explore`/`locate`/`search` identifican los
  archivos concretos antes de leerlos.

## Precondiciones
- Agente iniciado con la `Allowlist` apuntando a la raíz del proyecto (FR-025).
- El proyecto destino contiene el código y los tests que el usuario quiere
  entender.
- Los archivos a leer están dentro del perímetro autorizado.

## Flujo Principal
1. **Usuario**: "Explícame qué pruebas hace cada capa" / "¿Qué hace la capa de
   dominio?" / "Muéstrame el contenido de `tests/test_app.py`".
2. El agente percibe la intención de **explicar/entender código** y delega al
   bucle ReAct.
3. El agente **planifica** pasos que localizan los archivos relevantes y, sobre
   todo, pasos `leer_archivo` con `ruta` (raíz) y `archivo_relativo` concretos
   (p. ej. los archivos de test de cada capa) — no se conforma con la
   estructura (FR-049).
4. `leer_archivo` valida la raíz y el archivo resuelto contra la `Allowlist`
   (rechaza `..`/traversal, FR-025) y devuelve el contenido real tal como
   existe (`existe`, `contenido`, `total_lineas`, `truncado`) (FR-048 / SC-025).
5. El agente acumula las observaciones reales (resultados EXITO) y las evalúa:
   si el contenido relevante está leído, el criterio de éxito está satisfecho.
6. El agente **responde con profundidad**: organiza por capa/módulo, nombra los
   archivos concretos leídos y describe qué hace cada uno según su contenido
   real (clases, funciones, tests), conectando con la pregunta (FR-049 / SC-026).
7. El CLI muestra el panel "Razonamiento" (cada paso con razón, herramienta,
   parámetros y observación real, FR-035); el historial de acciones NO aparece
   por defecto (FR-050) y el usuario puede pedirlo con `--mostrar-historial`.

## Flujo Alternativo A — Archivo inexistente
1. `leer_archivo` devuelve `existe=false` y `contenido=""`.
2. El agente informa la ausencia sin inventar contenido (FR-008 / SC-002).
3. Si hay más evidencia obtenible, continúa el bucle; si no, responde con
   `confianza` `limitada` o `sin_informacion`.

## Flujo Alternativo B — Fuera del perímetro
1. La raíz o el archivo resuelto quedan fuera de la `Allowlist` (o usan `..`).
2. `leer_archivo` rechaza la lectura con error explícito; no accede (FR-025 /
   SC-011).
3. El agente re-planifica (paso alternativo dentro del perímetro) o informa la
   imposibilidad con honestidad (FR-036 / FR-019).

## Flujo Alternativo C — Evidencia insuficiente
1. El contenido observado no permite responder la intención (p. ej. no hay
   tests para una capa).
2. El agente responde con honestidad y `confianza` no alta, y sugiere el
   siguiente paso en "Recomendaciones" (FR-017 / FR-049).

## Flujo Alternativo D — Búsquedas masivas
1. `search` con regex amplio podría volcar millones de caracteres.
2. `search` acota con `max_ocurrencias` (default 200) y lo avisa con `nota`
   (honestidad, FR-019); el agente prefiere `leer_archivo` sobre archivos
   concretos para análisis profundos.

## Reglas de Negocio
- **Solo lectura**: `leer_archivo` no modifica nada y no requiere autorización
  (no es una acción sensible); toda lectura respeta la `Allowlist` (FR-025).
- **Honestidad**: el contenido se cita tal como existe; nunca se inventa ni se
  presenta un archivo truncado como completo (FR-048 / SC-025).
- **Profundidad**: la respuesta explica el contenido real observado por
  capa/módulo citando archivos concretos, no repite solo nombres (FR-049 /
  SC-026).
- **Confianza**: sin evidencia suficiente la confianza no puede ser alta
  (SC-017 / FR-019).
- **Trazabilidad**: cada paso (razón + herramienta + parámetros + observación)
  queda visible en "Razonamiento"; el historial de acciones es opcional en el
  CLI (FR-035 / FR-050).
- **Redacción**: secretos en contenidos leídos se redactan en respuestas,
  historial y logs (FR-021 / SC-008).

## Postcondiciones
- El agente leyó el contenido real de los archivos relevantes dentro del
  perímetro y respondió con profundidad anclada en evidencia real (o informó la
  ausencia/imposibilidad con honestidad).
- La sesión quedó trazada en "Razonamiento" (paso a paso) y, si se pidió, en el
  historial visible.
- Ningún contenido inventado, ningún archivo fuera del perímetro leído.
