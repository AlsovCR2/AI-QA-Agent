# UC-007 - El agente informa límites y evita inventar información

| Campo | Valor |
|-------|-------|
| **ID** | UC-007 |
| **Título** | El agente informa límites y evita inventar información |
| **Prioridad** | P3 |
| **Estado** | Aprobado |
| **Versión** | 1.0 |
| **Fecha** | 2026-08-11 |

## Actores

- **Usuario**: usuario del agente que confía en que las respuestas sean
  honestas sobre lo conocido.

## Descripción

El agente reconoce cuándo no posee suficiente información, cuándo ninguna
herramienta disponible puede atender la solicitud, o cuándo una herramienta
devuelve un error o resultado inválido. En estos casos informa su falta de
confianza o de datos, no inventa resultados y maneja los errores de forma
explícita. También filtra u oculta cualquier secreto detectado y sugiere ajustes
a la solicitud cuando no hay herramienta adecuada.

## Disparador

Una de las siguientes condiciones se presenta durante una interacción:

1. El agente carece de información suficiente para responder con confianza.
2. Una herramienta devuelve un error o un resultado inválido.
3. Ninguna herramienta disponible puede atender la solicitud.
4. Un resultado de herramienta contiene secretos o credenciales.

## Precondiciones

1. El agente está disponible y operativo.
2. Existe al menos una de las condiciones descritas en el disparador.

## Flujo Principal 1 - Información insuficiente

1. El usuario envía una solicitud para la que el agente carece de información
   suficiente.
2. El agente reconoce que no puede obtener la información necesaria.
3. El agente informa al usuario su falta de confianza o de datos.
4. El agente **no** inventa resultados.
5. El caso de uso termina.

## Flujo Principal 2 - Ninguna herramienta adecuada

1. El usuario envía una solicitud que ninguna herramienta disponible puede
   atender.
2. El agente determina que no existe una herramienta adecuada.
3. El agente informa al usuario que no puede atender la solicitud con las
   herramientas disponibles.
4. El agente sugiere ajustes a la solicitud.
5. El agente se abstiene de ejecutar herramientas inadecuadas o de forzar una
   ejecución.
6. El caso de uso termina.

## Flujo Principal 3 - Error o resultado inválido de herramienta

1. El agente ejecuta una herramienta.
2. La herramienta devuelve un error o un resultado inválido.
3. El agente valida el resultado y detecta que no es válido.
4. El agente maneja el fallo explícitamente.
5. El agente **no** presenta el resultado como válido.
6. El caso de uso termina.

## Flujo Principal 4 - Detección de secretos

1. El resultado de una herramienta contiene secretos o credenciales (tokens, API
   keys, etc.).
2. El agente detecta los secretos.
3. El agente filtra u oculta los secretos.
4. El agente muestra el resultado sin exponer los secretos en la respuesta, el
   historial visible o los logs.
5. El caso de uso termina.

## Postcondiciones

1. El agente nunca presenta información inventada o resultados inválidos como
   válidos.
2. Cuando no puede responder con confianza, lo comunica explícitamente.
3. Cuando no hay herramienta adecuada, informa y sugiere ajustes sin forzar una
   ejecución.
4. Los errores de herramienta se manejan de forma explícita.
5. Los secretos detectados se ocultan o filtran en respuestas, historial y logs.

## Trazabilidad

- **User Story**: US-7 (El agente informa límites y evita inventar información).
- **Requisitos funcionales**: FR-017, FR-018, FR-019, FR-021, FR-022, FR-023.
- **Principios de la constitución**: IX (Manejo seguro de errores), XI
  (Seguridad de información y credenciales), VII (Validación y contratos), VI
  (Determinismo).
- **Criterios de éxito**: SC-002, SC-005, SC-008, SC-009.

## Notas

Caso de uso **transversal**: sus reglas aplican como restricción sobre todos los
demás casos de uso (UC-001 a UC-006). La honestidad sobre lo desconocido es un
requisito de confianza innegociable y la fuente de verdad de los resultados es
siempre la información real del proyecto obtenida a través de las herramientas.
