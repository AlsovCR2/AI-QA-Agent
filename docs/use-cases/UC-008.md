# UC-008 - El agente analiza la cobertura de código de las pruebas

| Campo | Valor |
|-------|-------|
| **ID** | UC-008 |
| **Título** | El agente analiza la cobertura de código de las pruebas |
| **Prioridad** | P3 |
| **Estado** | Aprobado |
| **Versión** | 1.0 |
| **Fecha** | 2026-08-11 |

## Actores

- **Usuario**: profesional de QA que desea conocer la cobertura de código de las
  pruebas del proyecto para priorizar más pruebas.

## Descripción

El usuario solicita analizar la cobertura de código de las pruebas del proyecto.
El agente ejecuta el comando de cobertura autorizado (por ejemplo, sobre el
conjunto de pruebas autorizado) y reporta la cobertura real, tanto global como
por archivo. Cuando la ejecución de cobertura falla o no está disponible, el
agente informa el estado de forma explícita sin presentar cobertura inventada.

## Disparador

El usuario solicita analizar la cobertura de código de las pruebas del proyecto.

## Precondiciones

1. El usuario tiene acceso explícito y autorizado al proyecto.
2. Existe un entorno de ejecución de pruebas y de cobertura disponible.
3. El comando de cobertura forma parte de la allowlist de comandos seguros y
   autorizados.
4. La herramienta de análisis de cobertura está disponible.

## Flujo Principal

1. El usuario solicita analizar la cobertura de código de las pruebas.
2. El agente verifica que el comando de cobertura está autorizado (allowlist).
3. El agente ejecuta la herramienta de cobertura sobre el conjunto autorizado.
4. La herramienta devuelve la cobertura real global y por archivo.
5. El agente valida el resultado obtenido.
6. El agente reporta la cobertura real global y por archivo.
7. El agente muestra el historial visible de la ejecución y su resultado.
8. El caso de uso termina.

## Flujo de Excepción 4a - Fallo de la ejecución de cobertura

1. La ejecución de cobertura falla (entorno, configuración, etc.).
2. El agente reporta de forma explícita que la cobertura no pudo obtenerse.
3. El agente **no** presenta cobertura inventada.
4. El agente sugiere revisar el entorno o la configuración.
5. El caso de uso termina.

## Flujo de Excepción 4b - Herramienta de cobertura no disponible

1. La herramienta de cobertura no está disponible en el entorno.
2. El agente informa explícitamente que la cobertura no está disponible.
3. El agente **no** inventa valores de cobertura.
4. El caso de uso termina.

## Postcondiciones

1. El usuario recibe la cobertura real (global y por archivo) cuando el análisis
   se ejecuta correctamente.
2. Ante fallo o ausencia de la herramienta, se informa el estado explícitamente
   sin presentar cobertura inventada.
3. El historial visible registra la ejecución y su resultado.

## Trazabilidad

- **User Story**: US-10 (El agente analiza la cobertura de código).
- **Requisitos funcionales**: FR-030, FR-031.
- **Principios de la constitución**: IV (Seguridad y mínimo privilegio), VII
  (Validación y contratos), VIII (Observabilidad y trazabilidad), IX (Manejo
  seguro de errores).
- **Criterios de éxito**: SC-002, SC-005, SC-011, SC-014.

## Notas

La ejecución del comando de cobertura se limita a la allowlist de comandos
seguros y al conjunto de pruebas autorizado (SC-011). Las reglas de autorización
(UC-006) y de honestidad (UC-007) aplican dentro de este caso de uso.
