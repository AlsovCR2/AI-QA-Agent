> persistencia o `.qa_sessions`.

## Objetivo
El usuario interactúa con el agente en modo chat natural (múltiples turnos),
el agente recuerda el contexto de la conversación, puede asignarse tareas a sí
mismo o recibirlas del usuario, y las sesiones se pueden guardar y reanudar.

## Actores
- **Usuario** (humano) — mantiene una conversación multi-turno.
- **Agente Conversacional** — responde, razona, delega al bucle ReAct (Phase 12)
  cuando la intención es análisis QA, y gestiona su propia lista de tareas.

## Precondiciones
- Agente iniciado en modo interactivo (`qa-agent --ruta <proyecto>` sin `--pregunta`).
- Proyecto con estructura conocida (p.ej. ReservaHotel).

## Flujo Principal

1. **Usuario**: "Hola, vamos a analizar el proyecto ReservaHotel."
   - Agente: saluda, confirma proyecto, crea `Conversacion` nueva, registra `Turno 1`.
2. **Usuario**: "¿Cuáles son las clases más críticas para probar en la capa BLL?"
   - Agente: detecta intención QA → delega al **bucle ReAct** (Phase 12) →
     planifica (explore + locate/search) → ejecuta → observa → responde priorizando
     `ReservacionBL`, `PagoBL`, `UsuarioBL` (lógica de negocio) + recomendaciones.
   - Agente registra `Turno 2` con `razonamiento_ref` apuntando a las
     `Observacion` del bucle ReAct.
   - Agente **aprende**: guarda en `hechos` que "BLL = lógica de negocio, crítico para tests".
3. **Usuario**: "Crea una tarea para revisar la cobertura de ReservacionBL."
   - Agente: crea `TareaAgente(titulo="Revisar cobertura ReservacionBL",
     descripcion="...", prioridad=1, etiquetas=["cobertura","bll"])`, la añade a
     `Conversacion.tareas`, responde confirmando.
3b. **Usuario**: "/tarea run <id>"
   - Agente: convierte la tarea en una `Intencion` QA, la delega al bucle ReAct
     (planifica con `analyze_coverage`), ejecuta, y:
     - con evidencia real → marca `completada` y guarda `resultado`.
     - sin evidencia → marca `bloqueada` y guarda el motivo.
   - El resultado queda persistido con la sesión.
4. **Usuario**: "¿Qué tareas tengo pendientes?"
   - Agente: lista `Conversacion.obtener_tareas_pendientes()` → muestra la tarea.
5. **Usuario**: "Guarda la sesión y salimos."
   - Agente: `SesionManager.guardar(conversacion)` → persiste a JSON.
6. **Próximo día**: Usuario reanuda con `qa-agent --sesion <id>`.
   - Agente: `SesionManager.cargar(id)` → restaura `Conversacion` con historial,
     hechos aprendidos ("BLL crítico"), tareas pendientes.
   - Usuario: "Continúa con la tarea de cobertura."
   - Agente: recupera tarea, detecta intención QA → delega a ReAct con
     `analyze_coverage` → ejecuta → responde con reporte real.

## Flujo Alternativo (conversación general, no QA)
- Usuario: "¿Cómo estás?" / "Explícame qué es un agente ReAct."
- Agente: responde directo desde el LLM (modo chat), sin delegar al bucle ReAct,
  registra `Turno` sin `razonamiento_ref`.

## Reglas de Negocio
- **Memoria corta**: últimos 5 turnos + resumen se inyectan en `Intencion.contexto`
  para `planificar`/`razonar` del bucle ReAct.
- **Memoria larga**: `hechos` y `preferencias` en `Memoria` persisten entre sesiones.
- **Tareas**: CRUD completo; estados `pendiente` → `en_progreso` → `completada`/`bloqueada`.
- **Persistencia**: `SesionManager.guardar/cargar/listar` (JSON o SQLite).
- **Delegación**: si la intención requiere análisis QA (explorar, localizar, buscar,
  ejecutar pruebas, cobertura), se usa el `Agent` ReAct como herramienta interna;
  si es conversación general, el LLM responde directo.

## Postcondiciones
- Conversación guardada con historial completo, hechos, tareas y resumen.
- Usuario puede reanudar en cualquier momento con el mismo contexto.
- Trazabilidad: cada turno QA vincula a observaciones reales del bucle ReAct.
