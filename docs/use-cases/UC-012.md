# UC-012: El agente realiza acciones destructivas sobre el proyecto (crear, editar, eliminar archivos)

> **Estado: Aprobado (implementado)** — Phase 14 (T095-T103), suite 272 tests
> verde. Herramientas `crear_archivo`/`editar_archivo`/`eliminar_archivo`,
> `BackupManager` (`.qa-backup/`), enrutamiento determinista y autorización
> human-in-the-loop tanto en `--pregunta` como en modo chat.

## Objetivo
El usuario solicita al agente **modificar el proyecto**: crear archivos nuevos,
editar el contenido de archivos existentes o eliminar archivos. El agente
ejecuta la operación de forma segura: solo dentro del perímetro autorizado, con
autorización explícita (human-in-the-loop), respaldo del estado previo y
verificación del resultado real antes de responder.

## Actores
- **Usuario** (humano) — solicita la operación destructiva y la autoriza o
  deniega.
- **Agente** (bucle ReAct) — planifica, ejecuta la herramienta destructiva,
  gestiona la autorización, el backup y la verificación.
- **Herramientas destructivas** — `crear_archivo`, `editar_archivo`,
  `eliminar_archivo` (deterministas, sobre el filesystem).
- **BackupManager** — respalda el estado original antes de modificar/eliminar.

## Precondiciones
- Agente iniciado con la `Allowlist` apuntando a la raíz del proyecto (FR-025).
- El usuario está disponible para autorizar o denegar la operación sensible
  (SC-004).
- La ruta objetivo está dentro del perímetro autorizado.

## Flujo Principal

1. **Usuario**: "Crea el archivo `src/config/ajustes.py` con contenido de
   ejemplo" / "Edita la línea 3 de `BLL\ClienteBL.cs`" / "Elimina el archivo
   obsoleto `docs/viejo.md`".
2. El agente detecta intención de análisis + modificación → delega al **bucle
   ReAct** y planifica un paso con la herramienta destructiva adecuada
   (`crear_archivo`/`editar_archivo`/`eliminar_archivo`).
3. El agente valida el paso: herramienta real, parámetros dentro del esquema
   (FR-033), ruta dentro de la `Allowlist` (FR-025) y sin conflicto (crear
   inexistente / editar-eliminar existente).
4. La herramienta requiere autorización → el agente crea la `AccionSensible`
   pendiente y **suspende la ejecución** solicitando autorización al usuario
   (FR-015/016, SC-004).
5. **Usuario** autoriza la operación.
6. Para `editar_archivo`/`eliminar_archivo`, el `BackupManager` copia el estado
   original (con timestamp) a `.qa-backup/` (FR-045).
7. El agente ejecuta la operación real sobre el archivo.
8. El agente **verifica el estado real** (explore/locate/search confirman el
   cambio o la ausencia) y responde con evidencia de éxito (FR-047).
9. El agente registra la acción en el historial visible (redactada, SC-008) y
   termina.

## Flujo Alternativo A — Autorización denegada
1. El usuario deniega la autorización (FR-016).
2. El agente no ejecuta la operación, registra el estado "denegada" y notifica.
3. Si el bucle ReAct puede, re-planifica con un paso alternativo no sensible
   (FR-036); si no, concluye informando la imposibilidad.

## Flujo Alternativo B — Fuera del perímetro o conflicto
1. La ruta está fuera de la `Allowlist`, o se intenta crear un archivo que ya
   existe, o editar/eliminar un archivo inexistente.
2. El agente rechaza la operación **sin modificar nada** y lo informa
   explícitamente (FR-042/043/044, FR-019).

## Flujo Alternativo C — Fallo de ejecución
1. La operación autorizada falla a mitad de camino (error del filesystem).
2. El agente reporta el fallo explícitamente (FR-018) y no presenta el resultado
   como válido.
3. Si se generó backup, queda disponible para restaurar el estado original
   (FR-045).

## Reglas de Negocio
- **Perímetro**: toda operación destructiva actúa SOLO dentro de la `Allowlist`
  (FR-025 / SC-022); cualquier ruta fuera se rechaza.
- **Autorización**: ninguna operación de crear/editar/eliminar se ejecuta sin
  autorización explícita (FR-046 / SC-021); la autonomía del agente nunca se
  impone sobre las políticas de seguridad (principio V).
- **Backup**: editar y eliminar requieren respaldo previo del estado original
  (FR-045 / SC-023).
- **Verificación**: el resultado se confirma con evidencia real antes de
  responder; no se afirman cambios que no ocurrieron (FR-047 / SC-024).
- **Honestidad**: ante conflicto o fallo, se informa sin inventar resultados
  (FR-019 / SC-002).
- **Redacción**: secretos redactados en respuestas, historial y logs (FR-021).

## Postcondiciones
- La operación solicitada se ejecutó solo con autorización y dentro del
  perímetro, o fue rechazada sin modificar nada.
- En modificaciones/eliminaciones, el estado original queda respaldado en
  `.qa-backup/`.
- El resultado (éxito/fracaso/denegación) queda registrado en el historial
  visible y en la respuesta, con evidencia real.
