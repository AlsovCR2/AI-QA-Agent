# UC-009 - El agente genera casos de prueba sugeridos

| Campo | Valor |
|-------|-------|
| **ID** | UC-009 |
| **Título** | El agente genera casos de prueba sugeridos |
| **Prioridad** | P2 |
| **Estado** | Aprobado |
| **Versión** | 1.0 |
| **Fecha** | 2026-08-11 |

## Actores

- **Usuario**: profesional de QA que desea generar casos de prueba sugeridos para
  una función o componente del proyecto.

## Descripción

El usuario solicita al agente generar casos de prueba sugeridos (happy path,
edge cases, negativos) para una función o componente. El agente identifica el
código real pertinente del proyecto y propone casos que citan esas fuentes reales
como evidencia. Cuando no existe código relevante, el agente comunica la falta de
evidencia y no inventa casos ni fuentes.

## Disparador

El usuario solicita generar casos de prueba sugeridos para una función o
componente.

## Precondiciones

1. El usuario tiene acceso explícito y autorizado al proyecto.
2. El agente puede localizar el código real de la función o componente.
3. La herramienta de generación de casos de prueba está disponible.

## Flujo Principal

1. El usuario solicita casos de prueba sugeridos para una función o componente.
2. El agente localiza el código real pertinente del proyecto.
3. El agente analiza el código real (firmas, ramas, manejo de errores, entradas).
4. El agente propone casos de prueba sugeridos.
5. Cada caso propuesto cita como fuente el código real del proyecto.
6. El agente presenta los casos sugeridos y muestra el historial visible.
7. El caso de uso termina.

## Flujo de Excepción 4a - Sin código relevante

1. No se encuentra código real relevante para el objetivo solicitado.
2. El agente comunica explícitamente la falta de evidencia.
3. El agente **no** inventa casos de prueba ni fuentes.
4. El agente sugiere ajustar la solicitud o indicar otra función/componente.
5. El caso de uso termina.

## Postcondiciones

1. El usuario recibe casos de prueba sugeridos que citan código real del proyecto.
2. Ante ausencia de código, se comunica la falta de evidencia sin inventar casos.
3. El historial visible registra la ejecución y su resultado.

## Trazabilidad

- **User Story**: US-9 (El agente genera casos de prueba sugeridos).
- **Requisitos funcionales**: FR-028, FR-029.
- **Principios de la constitución**: VIII (Observabilidad y trazabilidad), IX
  (Manejo seguro de errores), II (Modularidad), VII (Validación y contratos).
- **Criterios de éxito**: SC-002, SC-005, SC-006, SC-013.

## Notas

Los casos generados son **sugerencias** y se limitan a aquello respaldado por la
evidencia del código real del proyecto (UC-007). Las reglas de honestidad (UC-007)
aplican dentro de este caso de uso.
