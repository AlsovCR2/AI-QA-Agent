# UC-005 - El agente ejecuta y analiza pruebas automatizadas

| Campo | Valor |
|-------|-------|
| **ID** | UC-005 |
| **Título** | El agente ejecuta y analiza pruebas automatizadas |
| **Prioridad** | P2 |
| **Estado** | Aprobado |
| **Versión** | 1.0 |
| **Fecha** | 2026-08-11 |

## Actores

- **Usuario**: profesional de QA que desea ejecutar pruebas automatizadas del
  proyecto y revisar sus resultados.

## Descripción

El usuario solicita ejecutar o analizar pruebas automatizadas del proyecto. El
agente ejecuta la operación sobre el conjunto de pruebas autorizado y reporta
los resultados reales obtenidos. Cuando una prueba falla o no puede ejecutarse,
el agente reporta el fallo de forma explícita y delimita la posible causa a
aquello que la evidencia respalda.

## Disparador

El usuario solicita ejecutar o analizar pruebas automatizadas del proyecto.

## Precondiciones

1. El usuario tiene acceso explícito y autorizado al proyecto.
2. Existe un entorno de ejecución de pruebas disponible.
3. El conjunto de pruebas está autorizado por el usuario o por la configuración
   del entorno.
4. La herramienta de ejecución/análisis de pruebas está disponible.

## Flujo Principal

1. El usuario solicita ejecutar o analizar pruebas automatizadas.
2. El agente verifica que el conjunto de pruebas está autorizado.
3. El agente identifica la herramienta pertinente y la ejecuta sobre el conjunto
   autorizado.
4. La herramienta devuelve los resultados reales de la ejecución.
5. El agente valida el resultado obtenido.
6. El agente reporta el estado real de las pruebas ejecutadas.
7. El agente muestra el historial visible de la ejecución y su resultado.
8. El caso de uso termina.

## Flujo de Excepción 4a - Prueba fallida

1. Una o más pruebas fallan durante la ejecución.
2. La herramienta devuelve los errores reales de las pruebas fallidas.
3. El agente reporta el fallo de forma explícita.
4. El agente presenta el error real obtenido.
5. El agente delimita la posible causa únicamente a lo que la evidencia
   sustenta.
6. El agente **no** atribuye una causa no respaldada por la evidencia.
7. El caso de uso termina.

## Flujo de Excepción 4b - Prueba no ejecutable

1. Una prueba no puede ejecutarse (falta de entorno, configuración, etc.).
2. El agente reporta de forma explícita que la prueba no pudo ejecutarse.
3. El agente no inventa resultados para dicha prueba.
4. El caso de uso termina.

## Postcondiciones

1. El usuario recibe el estado real de la ejecución de las pruebas.
2. Los fallos se comunican explícitamente con el error real y sus causas se
   delimitan a lo respaldado por la evidencia.
3. El historial visible registra la ejecución y su resultado.

## Trazabilidad

- **User Story**: US-5 (El agente ejecuta y analiza pruebas automatizadas).
- **Requisitos funcionales**: FR-012, FR-013, FR-014.
- **Principios de la constitución**: VII (Validación y contratos), VIII
  (Observabilidad y trazabilidad), IX (Manejo seguro de errores), IV (Seguridad
  y mínimo privilegio).
- **Criterios de éxito**: SC-002, SC-005, SC-006.

## Notas

La ejecución de pruebas se limita a conjuntos autorizados por el usuario o por
la configuración del entorno. Las reglas de autorización (UC-006) y de
honestidad (UC-007) aplican dentro de este caso de uso.
